1. Project Overview & Technology Stack

Smart Kolhapur Guide is a lightweight, high-performance web application designed to promote cultural heritage, pilgrimage tourism, and eco-tourism in Kolhapur district, Maharashtra. It combines real-time client-side search, a browser-native voice assistant, and a multi-criteria hotel recommendation algorithm.

Backend Layer

Python 3 + Flask framework. Stateless RESTful JSON endpoints with in-memory dataset indexing.

Frontend Layer

Semantic HTML5, CSS3 with responsive Grid/Flexbox, and pure Vanilla JavaScript (zero bulky frontend frameworks).

Structured Data Layer

JSON datasets (tourist_places.json with {{ places_count }} destinations, hotels.json with {{ hotels_count }} stays).

Voice Engine

W3C Web Speech API (SpeechRecognition & SpeechSynthesis) running 100% client-side with zero paid keys.

2. Recommendation Engine: Mathematical Formulation

The hotel recommendation engine uses a Multi-Criteria Decision Making (MCDM) weighted sum model that evaluates four key dimensional vectors:

A. Geospatial Proximity Calculation (Haversine Formula)

To compute the true great-circle spherical distance \(d\) between the hotel coordinates \((\phi_1, \lambda_1)\) and the selected tourist destination \((\phi_2, \lambda_2)\):

a = sin²(Δφ / 2) + cos(φ1) · cos(φ2) · sin²(Δλ / 2)
c = 2 · atan2(√a, √(1 − a))
d = R · c   (where R = 6371 km)

Proximity Sub-Score (\(S_{\text{dist}}\)): Scaled between 0 and 100 using linear decay over an effective radius of 35 km:
\(S_{\text{dist}} = \max\left(0, 100 \times \left(1 - \frac{d}{35}\right)\right)\) (with \(S_{\text{dist}} = 100\) if \(d \le 1.0\text{ km}\)).

B. Budget Fit Sub-Score (\(S_{\text{price}}\))

Evaluates how closely the hotel price per night \(P\) aligns with user budget \([B_{\min}, B_{\max}]\):

  • If \(B_{\min} \le P \le B_{\max}\): \(S_{\text{price}} = 100 - \left(\frac{P - B_{\min}}{B_{\max} - B_{\min}} \times 25\right)\) (giving 75 to 100 points, rewarding higher affordability).
  • If \(P < B_{\min}\): Awarded top value score of 95.
  • If \(P > B_{\max}\): Progressive penalty applied: \(S_{\text{price}} = \max\left(0, 80 - \frac{P - B_{\max}}{50}\right)\).

C. Rating & Facility Overlap Sub-Scores (\(S_{\text{rating}}\) & \(S_{\text{fac}}\))

  • Rating Score: \(S_{\text{rating}} = \left(\frac{\text{Rating}}{5.0}\right) \times 100\)
  • Facility Match Score: Jaccard set intersection ratio: \(S_{\text{fac}} = \frac{|F_{\text{hotel}} \cap F_{\text{req}}|}{|F_{\text{req}}|} \times 100\) (or 100 if no specific facilities requested).

D. Composite Multi-Criteria Score (\(S_{\text{total}}\))

S_total = w_dist · S_dist + w_price · S_price + w_rating · S_rating + w_fac · S_fac

Dynamic Priority Weight Presets:
• Balanced: \(w = [0.35, 0.25, 0.20, 0.20]\)
• Proximity First: \(w = [0.55, 0.15, 0.15, 0.15]\)
• Budget First: \(w = [0.15, 0.55, 0.15, 0.15]\)
• Rating First: \(w = [0.15, 0.15, 0.55, 0.15]\)

3. College Viva / Mini-Project Defense Q&A

Q1: Why did you use Haversine distance instead of Euclidean distance?

Answer: Earth is an oblate spheroid. Latitude and longitude are angular coordinates on a sphere. Euclidean distance assumes a flat 2D plane and produces significant distortion, whereas the Haversine formula calculates the exact spherical geodesic arc length across Earth's radius (6,371 km).

Q2: How does the voice assistant operate without any cloud API keys?

Answer: It relies entirely on the HTML5 Web Speech API standard built natively into modern browsers. SpeechRecognition converts spoken acoustic audio to text on the client device, and SpeechSynthesis parses string tokens into synthesized speech audio locally.

Q3: What makes this project relevant to Data Science?

Answer: It implements structured feature extraction, non-linear feature normalization, set similarity metrics (Jaccard similarity for facilities), geospatial mathematical modeling, and multi-criteria weighted scoring algorithms (MCDM) to rank heterogeneous entities.
