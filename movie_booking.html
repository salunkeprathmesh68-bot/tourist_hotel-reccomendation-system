Academic Viva Guide

C++ Object-Oriented Programming (OOP) Implementation Guide

Detailed breakdown of how every required OOP concept is implemented in the underlying C++ source code (main.cpp).

1. Encapsulation

Classes like Movie, Theatre, and Booking have all attributes declared as private or protected, accessible strictly through getters, setters, and business rules.

2. Inheritance & Polymorphism

Abstract base class Seat defines pure virtual function virtual double calculatePrice() const = 0;. Subclasses RegularSeat and PremiumSeat override it dynamically at runtime.

3. Composition (Show HAS Seats)

Show contains a 2D matrix vector<vector<Seat*>> seatGrid. Implements the Rule of Three with a deep-copy destructor to eliminate memory leaks.

4. Permanent File Handling (<fstream>)

Serialized state storage across four files: movies.txt, theatres.txt, shows.txt, and bookings.txt. Survives application restarts.

Top Viva Questions to Ace Your Presentation

Q1: Why is a 2D array / vector chosen for seat storage instead of a 1D list?

Ans: A cinema hall has rows (A, B, C...) and columns (1, 2, 3...). A 2D matrix directly maps physical spatial coordinates into O(1) random-access memory lookup.

Q2: Where is dynamic polymorphism demonstrated?

Ans: In seat billing calculations via pointer dispatch: Seat* s = show.getSeat(code); double price = s->calculatePrice();. The runtime resolves whether it's a RegularSeat or PremiumSeat with recliner surcharge.

Q3: How is double-booking prevented?

Ans: A 3-tier validation: 1) format validity check, 2) atomic occupancy check isSeatBooked(), and 3) transaction-level deduplication to prevent picking the same seat twice.
